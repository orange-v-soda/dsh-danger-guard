# dsh-danger-guard

通过 DSH 自带的工具审核接口（`tools/pre-execute`），在工具真正执行前做一次确定性的硬性检查：命中固定规则就直接拒绝，不经过模型判断。

## 安装

在插件管理器的目标里填：

```
github:orange-v-soda/dsh-danger-guard
```

## 适用场景

- 想开启 Auto review，但对模型临场判断的稳定性有顾虑——它可以作为一道确定性的底线，叠在模型审核前面。
- 想给 agent 划一条简单的权限边界，又不想接整套沙箱配置。

规则写死、可读，拒绝理由会明确回给模型，行为是可预期的。

## 默认规则

只覆盖事故级操作，正常开发基本碰不到：递归强制删除根目录或系统目录、磁盘格式化、关机重启、放开根权限、fork bomb，以及对系统目录的写入。

`rm -rf ./dist`、正常删除工作区目录、写任意普通路径都不会被拦。

## 修改规则

全部在 `lib/index.js` 里。`checkSegment()` 管命令，`isProtectedPath()` 管路径，加一条规则就是加一个分支、返回一句理由，没有额外的配置层。

## 边界

确定性规则只能识别它写出来的模式。变量拼接、`eval`、`xargs`、把命令写进脚本再执行、`run_code` 里直接调 Node 都绕得过去。它降低手滑概率，不替代沙箱。

## 声明

- **适配版本**：DSH `>= 0.2.1-rc.2`
- **开源协议**：MIT
